## 一、项目背景与要解决的问题

我们是北京交通大学 MEM 专业的研究生。在协助教务老师完成本专业排课时，我们深切感受到这项工作复杂、繁琐，而且信息共享困难。

MEM 专业目前设有全日制 4 个班级、非全日制周末班 2 个班级、非全日制集中班 2 个班级。每个班级都有不同的课表，每学期有十几门课程，课程的授课教师、上课地点也不相同。排课时不仅要根据培养方案调整本学期课程，还要考虑教师、时间和教室冲突；同时，还需要兼顾本科、博士班级的排课情况，避免共用教师或教室时发生冲突。

以往主要依靠教务老师丰富的业务经验，在 Excel 中反复调整，再由其他老师、助管同学协助核对。这种方式存在几个问题：

- **调整成本高**：课程、教师、周次和教室分散在不同表格中，修改一处往往需要同步多处。
- **冲突难以及时发现**：主要依赖人工核对，容易遗漏教师冲突、教室占用或课程重复安排。
- **数据提取不方便**：需要按班级、教师或周次查看时，筛选和整理比较费时。
- **共享与协作困难**：文件多次传递后容易出现版本不一致，修改记录和当前结果也不够清晰。

针对这些真实需求，我们使用 Qoder 开发了「研究生排课工作台」，希望把排课流程搬到线上，通过更便捷的操作完成课程安排、冲突检查和课表输出。

## 二、我们做了什么

「研究生排课工作台」是一个纯前端、无需登录即可体验的在线排课工具。它把学期、班级、课程、教师、教室、教学任务和节假日集中管理，提供从基础信息维护到课表导出的完整操作链路。

目前主要包含以下能力：

### 1. 基础信息与教学任务管理

可以统一维护班级、课程、教师、教室场地、学年学期和节假日，并在教学任务中设置任课教师、授课班型、合班关系和上课周次。

系统预置了可直接体验的数据：9 个班级（增加了一个非全日制集中班合班的班级，实际还是8个）、53 门课程、50 位教师、6 间教室、71 项教学任务和 51 条节假日信息，覆盖全日制、周末班和集中班三类排课场景。

### 2. 可视化排课

排课页采用网格方式展示星期、节次和课程。用户可以：

- 从左侧选择教学任务，再点击目标时间格完成安排；
- 拖动已排课程调整星期和节次；
- 为课程选择教室或填写线上会议链接；
- 对集中班按周查看和调整课表；
- 使用“一键自动排课”生成待检查的草稿。

所有修改在点击保存前都只保留为草稿，页面会显示新增、修改和删除数量，方便用户确认本次操作。

### 3. 冲突检查与学期体检

系统使用周次位图判断两条排课是否真正重叠：只有星期相同、节次区间相交，并且存在共同上课周时，才视为时间冲突。

保存前会检查教师时间冲突、教室占用冲突和同一教学任务重复排课。发现问题时，用户可以选择返回修改，也可以在明确确认后强制保存。

保存后还可以运行“学期体检”，通过 12 条规则扫描整个学期的排课，包括教师冲突、教室冲突、合班课程时间或地点不一致、周次缺失或越界、课时超排或不足等，并直接定位到对应排课单。

### 4. 课表查看与导出

课表支持班级视角和教师视角，也支持简版与逐周查看。简版会把同一时间格的课程按周次合并，逐周视图更适合集中班使用。

用户可以在浏览器中直接导出标准 xlsx 文件，也可以批量导出全部排课单，便于打印、核对和线下共享。

### 5. 本地持久化与演示恢复

数据保存在当前浏览器的 IndexedDB 中，刷新页面后仍可保留。页头提供“重置演示数据”功能，可以一键恢复初始状态，方便反复演示。

需要说明的是，当前公开站点是**参赛演示版本**，用于展示完整操作流程和界面效果，数据持久化采用**浏览器本地持久化**，还不是云端多人共享。真实系统采用 **Vue + MySQL 在本地部署**，由本地数据库完成数据持久化。教师页面中的学院、办公室、邮箱等扩展信息为演示资料，页面内已明确标注。后续可进一步部署为多人共享的在线教务平台。

## 三、操作步骤

系统按照“基础信息 → 教学任务 → 排课”的顺序组织操作，用户可以从工作台总览进入对应页面。

### 1. 维护基础信息

首先在“基础信息”中维护排课所需的基础数据，例如：

- 创建班级，设置班级代码、学习方式、授课形式和班级容量；
- 创建课程，设置课程号、学分、学时、考核方式和授课模式；
- 维护授课老师，包括姓名、职称、学院、办公室等基本信息；
- 创建上课地点，包括教室编号、所在楼栋、校区、教室类型和容量；
- 维护学年学期、总周数、起止日期和节假日安排。

这些信息会作为后续教学任务和排课的可选数据。

### 2. 维护教学任务

教学任务是学期、班级、课程、老师等信息的动态组合。进入“教学任务”页面后，可以根据当前学期的实际情况新增或调整任务，例如：

- 选择教学任务所属学期和授课班型；
- 关联课程及对应班级；
- 设置任课老师和合班关系；
- 选择上课周次；
- 维护任务的总课时和每次课节数等信息。

培养方案或实际教学安排变化时，可以先调整教学任务，再进入排课工作台完成时间与地点安排。

### 3. 完成排课

进入“排课工作台”后，按以下方式操作：

1. 在页面上方选择需要排课的班级排课单。
2. 点击左侧列表中的教学任务，将其设为当前任务。
3. 点击右侧周次表中的目标时间格，即可添加课程信息。
4. 点击已添加的课程卡片，可以打开详情，编辑上课地点、线上会议链接等信息，也可以删除该条排课。
5. 如需调整时间，可以拖动课程卡片，或使用移动操作更换目标时间格。
6. 确认本次修改后，点击上方“保存”按钮完成落盘；如需撤销本次所有草稿修改，可点击“放弃改动”。

保存前，系统会检查教师、教室和重复排课等冲突。保存完成后，可以进入“学期体检”查看整个学期的问题，或进入“课表查看”按班级、教师等视角查看并导出课表。

## 四、Qoder 使用记录与项目过程

项目按“理解业务 → 搭建数据 → 实现排课 → 验证修复 → 发布文档”推进。Qoder 作为开发协作工具，参与了需求拆解、代码实现、问题定位、构建发布和文档整理。

### 1. Qoder 在项目中的使用方式

- **需求拆解与方案设计**：把教务老师基于 Excel 的排课流程拆分为基础信息、教学任务、排课工作台、学期体检和课表查看五个模块，并确定字段、页面和操作顺序。
- **数据建模与迁移**：将学期、班级、课程、教师、教室、教学任务、排课和节假日抽象为本地数据表；把真实业务数据脱敏后转换为前端可用的种子数据。
- **前端实现与重构**：使用 Vue 3、Vite、Pinia、Element Plus 和 Dexie 实现页面、组件、状态管理和本地持久化，并把原有排课交互重构为可在浏览器中直接运行的版本。
- **测试、构建与发布**：通过浏览器实际操作复现问题、查看控制台和数据库状态，完成生产构建后发布到 Qoder Sites，并整理项目说明、操作截图和图文版文档。

### 2. 开发过程记录

1. **需求梳理**：调研教务老师的真实排课流程，明确三类班型、合班、教师冲突、教室冲突、周次和课时等核心约束。
2. **数据建模**：建立班级、课程、教师、教室、学期、教学任务和排课单的数据关系；用 `week_pattern` 位图表示一个学期内的上课周分布。
3. **基础功能搭建**：完成 6 个页面、通用 CRUD、学期与班型筛选、教师演示信息标注，以及浏览器本地数据播种和重置。
4. **排课核心实现**：实现左侧任务与右侧周次网格联动、点击放置、拖拽换位、草稿状态、教室和线上链接编辑；非全日制按周末班和集中班分别控制可见星期。
5. **冲突与输出**：实现“星期相同 + 节次相交 + 周次位图相交”的冲突判定、贪心自动排课、12 条学期体检规则，以及简版/逐周课表和 xlsx 导出。
6. **实测与问题修复**：在浏览器中逐项复现并修复影响实际使用的问题，包括非全日制任务保存时的 IndexedDB 结构化克隆失败、周末班自动排课的星期偏移、集中班自动排课缺少周次键等。
7. **发布与回归**：完成生产构建和站点发布，并在线上重新验证周末班、集中班的自动排课、保存和刷新后保留；补充图文版项目说明和 9 张操作截图。

## 五、当前不足与后续完善

当前版本已经能够完成单浏览器内的排课、检查、查看和导出，但距离完整在线教务平台还有一定距离，后续计划重点完善以下方面：

1. **多人在线共享**：引入账号、权限和云端数据库，支持教务老师、任课教师和助管同学同时查看与维护，避免文件多版本传递。
2. **跨专业冲突检查**：在现有 MEM 数据基础上接入本科、博士班级的教师和教室数据，使冲突检查覆盖更多排课场景。
3. **Excel 导入与批量维护**：目前主要通过页面逐条维护或替换种子数据，后续将支持从培养方案和既有课表批量导入。
4. **自动排课能力增强**：当前自动排课是贪心辅助算法，可能出现部分任务无法放置，后续将加入更多约束和更完善的求解策略。
5. **协作与审计能力**：增加修改记录、问题处理状态、忽略规则和导出审批，方便追踪谁在何时调整了哪些课程。
6. **离线与移动端体验**：进一步完善 PWA 离线缓存和移动端操作，使排课人员在教室或办公室之外也能临时调整方案。

总的来说，本项目已经从“依靠 Excel 人工核对”迈出了第一步：把排课流程集中到一个在线工作台中，让安排、检查和输出更加直观。后续将继续向多人协作、跨专业资源统筹和真实教务数据接入方向完善。
