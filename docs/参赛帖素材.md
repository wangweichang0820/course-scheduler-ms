## 4️⃣ 正文（发帖主体 · 建议 5 段式）

### 🎯 我们解决的问题

MEM（工程管理硕士）项目每学期要为 9 个研究生班级（含全日制、非全日制周末班、非全日制集中班 3 类班型）排课，涉及 50 位教师、53 门课程、 6 间场地。**传统教务系统三大痛点**：

1. **重**：Spring + MySQL + Vue 三件套部署，学院机房才能跑
2. **慢**：排课冲突要等保存后服务端返回才知道
3. **不可离线**：老师出差、教室断网就完全不能改课

我用 Qoder 花了一个周末把原项目重构成纯前端版本 —— **保留核心交互与算法，把后端整个删掉**。

### 💡 核心思路

**分层复用旧项目 78% 代码，只重写 IO 层。**

```
旧 Sch_Clas_MS（FastAPI + MySQL）          新 mem-scheduler
─────────────────────────────────         ──────────────────────
backend/api/*.py       ← 全部删除 →      IndexedDB (Dexie)
backend/services/audit.py  ── 移植 →     src/engine/audit.js（20 → 12 条）
backend/services/conflicts.py ─ 移植 →   src/engine/conflicts.js
frontend/utils/*.js    ── 直接拷贝 ─→    src/utils/*.js（11 个纯函数）
frontend/components/*.vue ── 保留 →      src/components/*.vue（9 个纯 props 组件）
frontend/views/*       ── 改造 →         src/views/*（6 个页面）
```

**保留的核心资产**：
- **周次位图** `week_pattern`（如 `11111111000000000000` = 前 8 周上课）
- **三段重叠冲突判定**：`星期相同 ∧ 节次区间相交 ∧ 位图与运算非空`
- **CompactTimetable 简版课表算法**：同格同地点自动合并周次
- **ExcelJS 教务格式 xlsx 导出**：A4 横向、冻结表头、按班型自动裁列

### ✨ 5 大亮点

1. **⚡ 一键自动排课**（新增）—— 贪心遍历 (星期, 节次块, 教室) 三元组，避开教师 / 教室 / 同格占用；80% 场景一键铺满学期
2. **🎨 拖拽网格草稿** —— 已保存的 slot 落"实色"，本次未保存的改动落"虚线"，鼠标拖动即换格子，保存前不落盘
3. **🔍 学期体检 12 条规则** —— 8 项 error + 4 项 warning 一次性扫描全学期 slot，可跳转回排课页修复
4. **📊 位图周次选择器** —— 12 列 checkbox 一眼看完整个学期（当前学期 19 周）的分布，"1-8 周 / 9-16 周 / 单周 / 双周"一键预设
5. **📥 xlsx 一键导出** —— 教务直接可打印：A4 横向、按班型裁列、简版 / 分周版 / 全部班级 zip

### 🚀 Qoder 帮我做了什么

比赛要求"用 Qoder 完成"，我把工作分成 4 段：

| 段 | 我做的 | Qoder 做的 |
|----|--------|-----------|
| **规划** | 说清"删掉后端、保留网格、部署到 Qoder Sites" | 拆解为 16 项 TodoWrite，从脚手架 → 迁移 → 引擎 → 视图 → 构建 → 部署逐一实施 |
| **迁移** | 指路旧项目 `Sch_Clas_MS` 目录 | 逐层判定复用度：utils 直接拷贝 / components 删 17 个重型 dialog 保留 9 个纯组件 / views 全部重写 |
| **算法移植** | 说明"20 条精简到 12 条" | 读 Python `audit.py` 778 行 → 输出等价 JS `audit.js` 260 行 → 补上 `TYPE_META` 元数据供 UI 消费 |
| **验证 & 部署** | 说"跑 build 看看" | 修 `??` 与 `&&` 混合的语法错误 → 二次构建通过 → 生成 Qoder Sites 部署指引 |

**最惊艳的一刻**：我告诉它"数据层从 SQLAlchemy 换到 IndexedDB，其余视图尽量不改"，它主动想到在 store 里加 `enrichSlot` getter 补 `course_name / teacher_names`，让**页面渲染与 xlsx 导出共用同一份 `buildCompactModel`**，避免了页面看到 A、导出却是 B 的经典坑。

### 📈 数据规模（旧系统真实脱敏数据）

| 实体 | 数量 |
|------|------|
| 学期 | 2（当前 2026-2027 秋季，19 周） |
| 校区 / 教学楼 | 4 / 2 |
| 班级 | 9（3 类班型齐全） |
| 教师 | 50 |
| 课程 | 53（含合班课） |
| 场地 | 6 |
| 作息节次 | 7（1-6 节各 2 课时 + 第 7 节 1 课时） |
| 节假日 | 51 |
| 教学任务 | 71 |
| 排课单 / slot / 周组 | 1 / 16 / 3（其余 8 个班自动补空白排课单，可一键 ⚡自动排课） |

> 数据由 `scripts/build-real-seed.mjs` 从旧项目的 MySQL dump 转换而来，转换时逐项过脱敏映射（教师姓名 / 工号 / 班级 / 校区 / 教学楼 / 课程号 均为映射名），**无任何真实个人信息**。
>
> ⚠️ 说给评委听的一个细节：**脱敏映射表本身不随仓库分发**，而是在生成时通过环境变量 `MEM_MAP_PATH` 传入。因为映射表一旦公开，就能反推回真实姓名 —— 把它排除在仓库外是设计选择，不是遗漏。仓库里可直接看到脱敏结果（`src/seed/real-data.json`）与生成脚本全文，可自行复核。
